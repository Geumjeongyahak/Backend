# 관측

러너가 없으면 자동으로 쌓이는 것도 없다. **v2의 관측은 전부 사람과 에이전트가 정해진
자리에 적어서 생긴다.** 그 대가와 한계를 먼저 적는다.

## 왜 레포에 남기나

대화 세션은 끝나면 사라진다. 무엇을 왜 그렇게 정했는지가 세션 안에만 있으면 다음 주에
같은 논의를 처음부터 한다. **레포에 남은 것만 다음 사람이 읽는다.**

파생되는 것은 안 남긴다. 커밋 메시지가 말하는 것, diff가 말하는 것은 원장에 옮기지
않는다. 두 벌이 되면 갱신될 때 한쪽만 낡고, 낡은 쪽을 누군가 사실로 읽는다.

## 관측 포인트

흐름 위에서 무엇이 어디에 남는지다. **여기 없는 자리에서는 아무것도 안 남는다.**

```
ideate-issue
  20 구체화 ─────────────▶ (대화. 안 남는다)
  30 spec ───────────────▶ docs/issues/<번호>-<slug>/spec.md
  게이트 spec ────────────▶ gates-ledger.tsv
  40 이슈 생성 ───────────▶ GitHub issue      ← 무엇을 왜 할지의 원본

work-an-issue
  05 브랜치 ──────────────▶ git
  10 설계 ────────────────▶ docs/issues/<번호>-<slug>/plan.md
  게이트 plan ────────────▶ gates-ledger.tsv
  20 구현 ────────────────▶ 커밋 (무엇을 왜 고쳤나)
  30 테스트 ──────────────▶ 커밋 + verify.sh 출력
  40 리뷰 ────────────────▶ review.md · PR 코멘트 · findings-ledger.md

land-a-pr
  10 검증 ────────────────▶ PR 본문 「체크리스트」 (돌린 것만 체크)
  20 PR 본문 ─────────────▶ PR 「리뷰어에게」  ← 왜 저 방식이 아니었나
  게이트 land ────────────▶ gates-ledger.tsv
  40 병합 ────────────────▶ git
```

**이 레포의 PR 본문에는 「검증」 절이 없다.** 절은 일곱이고(개요 · 변경 유형 ·
변경 내용 · 관련 이슈 · 스크린샷 · 체크리스트 · 리뷰어에게), 검증 증거는
「체크리스트」의 체크와 「리뷰어에게」의 한 줄로 들어간다. 없는 절을 새로 만들지
않는다 — 최근 PR 일곱 건이 전부 같은 일곱 절이다.

## 원장 둘

레포에 커밋한다. 이슈 폴더는 이슈 하나의 이야기이고, **원장은 이슈를 가로지르는
이야기다.** 재발과 판단 습관은 한 이슈 안에서는 안 보인다.

### `harness/gates-ledger.tsv`

게이트에서 무엇을 묻고 뭐라 답했나. 한 줄이 한 판정이다.

```
date	issue	gate	question	answer	reason
```

| 열 | 무엇 |
|---|---|
| `date` | `YYYY-MM-DD` |
| `issue` | 이슈 번호. 없으면 `-` |
| `gate` | `spec` · `plan` · `land` |
| `question` | 게이트가 실어 보낸 숫자를 포함한 물음 |
| `answer` | `승인` · `다시` · `막힘` |
| `reason` | **`막힘`이면 필수.** 나머지는 비워도 된다 |

**`막힘`은 예약어다.** 근거를 못 대면 통과가 아니라 막힘이다. 사람이 "괜찮아
보이는데"로 넘긴 것과 근거를 적고 통과시킨 것은 여기서 구별돼야 한다.

이 원장이 답하는 질문은 하나다. **어떤 게이트가 항상 «승인»만 나오나.** 그 게이트는
판정을 안 하고 있는 것이고, 물음에 실어 보내는 숫자가 틀렸다는 뜻이다.

### `harness/findings-ledger.md`

codex 리뷰 지적 한 건이 한 행이다. 반려한 것도 적는다 — **반려한 지적이 나중에 사고로
돌아오는지가 이 원장을 두는 이유의 절반이다.**

```markdown
| 날짜 | 이슈 | 심각도 | 위험도 | 지적 | 판단 | 사유 |
```

`판단`은 `수용` 또는 `반려`다. `반려`면 `사유`가 필수다.

이 원장이 답하는 질문은 둘이다. **같은 종류의 결함이 반복되나** (그러면 그건 리뷰가
아니라 구조로 막을 것이다), **반려한 것이 다시 돌아오나** (그러면 반려 기준이 틀렸다).

## 못 재는 것

**빈칸을 0으로 쓰면 좋아 보인다.** 못 재는 것은 못 잰다고 적는다.

| 무엇 | 왜 못 재나 |
|---|---|
| 토큰·시간 | 러너가 없다. 세션이 자기 사용량을 안 남긴다 |
| 워크플로를 몇 번 돌렸나 | 돌린 흔적이 게이트를 지날 때만 남는다. 건너뛰면 안 남는다 |
| codex 리뷰를 안 부르고 병합한 횟수 | 안 부른 것은 아무 데도 안 남는다 |
| 게이트를 통째로 건너뛴 횟수 | 같은 이유다 |

마지막 둘이 이 설계의 구멍이다. **v2는 지켜진 것만 관측하고, 안 지켜진 것은 관측하지
못한다.** 원장이 비어 있으면 「일이 없었다」인지 「안 적었다」인지 구별할 수 없다.

그래서 원장을 볼 때는 **머지된 PR 수와 원장 행 수를 같이 본다.** PR 열 개에 게이트
행이 세 개면 일곱 번은 안 적은 것이다.

```bash
gh pr list --state merged --limit 50 --json number,mergedAt | jq length
wc -l < harness/gates-ledger.tsv
```

이 구멍을 막으려면 게이트를 강제하는 자리가 필요하고, 그건 러너다. 지금은 안 만든다.
[README의 v3 후보](README.md#v3-후보)에 적어 뒀다.

## 안 두는 것

| 무엇 | 왜 |
|---|---|
| 실시간 pane 보드 | 창은 편의지 계약이 아니다. 기록은 파일로 남는다 |
| `.harness/runs/` 같은 실행 로그 | 러너가 없어서 쓰는 주체가 없다 |
| 직군별 로그 파일 | 직군이 없다 |
| 세션 transcript 수집 | hook을 안 건다. 세션 설정을 건드리는 것은 v2 범위 밖이다 |
