# 전제

v2는 러너가 없다. 대신 CLI 둘과 검사 하나에 기댄다. 셋 중 하나라도 없으면 해당
단계가 통째로 비고, **비었다는 것을 아무도 안 알려준다.** 그래서 처음 돌리기 전에
여기를 확인한다.

플러그인 설치는 전제가 아니다. 절차는 전부 이 폴더 안에 있고, 진입점은
`.claude/skills/`가 갖는다. **이 레포를 여는 것 말고 준비할 것이 없다.**

## 1. gh CLI

이슈 생성·조회와 PR 생성이 전부 `gh`를 지난다. **GitHub issue가 유일한 원본**이고
외부 이슈 트래커를 두지 않는다.

```bash
gh --version        # 2.94.0 기준
gh auth status      # Logged in to github.com 이 떠야 한다
```

인증이 없으면 `ideate-issue`와 `land-a-pr`이 통째로 못 돈다.

## 2. codex CLI

적대적 리뷰의 유일한 자리다. **다른 프로세스이고 다른 모델이라 그것만으로 다른 눈이
된다.** 자기가 짠 것을 자기가 판정하지 않는 것이 이 도구를 두는 이유의 전부다.

```bash
codex --version     # 0.146.1 기준
```

없으면 `work-an-issue`의 리뷰 단계는 **건너뛰는 것이 아니라 막힌다.**
[codex-review.md](codex-review.md)를 본다.

GitHub의 `@codex review` 클라우드 봇은 안 쓴다. 왕복이 5~15분이라 고칠 때마다 느리고
회차를 우리가 못 정한다.

## 3. 검사

```bash
scripts/harness/verify.sh
```

**기준선은 워크플로를 시작하기 전에 확인한다.** 시작 전부터 빨간불이면, 뒤에서 나오는
실패가 이번 변경 때문인지 원래 그랬는지를 못 가린다.

## 4. 이슈 폴더

이슈 하나가 폴더 하나다.

```
docs/issues/<번호>-<slug>/
  spec.md      무엇으로 만드나      ideate-issue 가 남긴다
  plan.md      어떻게 만드나        work-an-issue 가 남긴다
  review.md    회차와 남은 지적 수  codex 리뷰가 남긴다
```

`<slug>`는 영문 소문자와 하이픈이고, 브랜치 이름의 뒷부분과 같은 것을 쓴다
(`feat/<번호>-<slug>`).

`docs/issue/`(단수)는 v2 이전에 쓰던 자리다. 건드리지 않는다.

## 안 쓰는 것

여기서 뺀 것들이다. 뺀 이유를 같이 적어 둔다 — 나중에 누가 다시 넣자고 할 때
같은 논의를 처음부터 안 하려고.

| 무엇 | 왜 뺐나 |
|---|---|
| wezterm · tmux pane 보드 | 실시간 화면이 없어도 기록은 파일로 남는다. 창은 편의지 계약이 아니다 |
| 셸 러너 (상태·게이트 판정·worktree) | 유지비를 낼 사람이 정해지기 전에는 막는 쪽을 안 세운다 |
| 플러그인 설치·scope 설정 | 절차가 레포 안에 있으면 설치가 필요 없다. 설치를 전제하면 안 걸린 사람에게는 단계 이름만 남는다 |
| 무인 실행 | 사람이 없는 구간을 만들려면 격리와 예산이 먼저다. 둘 다 없다 |
| 토큰·시간 측정 | 러너가 없어서 못 잰다. [observability.md](observability.md)에 못 잰다고 적어 둔다 |
