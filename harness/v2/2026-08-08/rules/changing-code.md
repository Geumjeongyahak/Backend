# 있는 코드를 고치는 규칙

## 고치기 전에 호출자를 전부 찾는다

공유 메서드 · 응답 DTO · 스키마를 고칠 때는 그것을 부르는 자리를 다 본 뒤에 손댄다.

```bash
grep -rn "<메서드 이름>" src/main/java src/test/java
```

증상이 보고된 경로 하나만 고치면 나머지 호출자는 깨진 채 남는다.

## 모든 호출자가 지나는 한 곳을 고친다

같은 수정이 호출자마다 복사되고 있으면 고칠 자리를 잘못 고른 것이다. 가드 하나를
공유 지점에 두는 것이 호출자 다섯에 하나씩 두는 것보다 작고, 여섯째 호출자가 생겨도
안 빠진다.

## 고치라는 것만 고친다

지나가는 김에 한 이름 변경 · 포맷 변경이 diff에 섞이면 리뷰가 진짜 변경을 못 본다.
눈에 띈 다른 결함은 고치지 말고 PR의 `리뷰어에게`에 적거나 이슈로 남긴다.

## 어긋났을 때 알아채는 법

같은 몇 줄이 두 파일 이상에 복사됐으면 공유 지점을 놓친 것이다.
리뷰에서 「이 경로만 쓰는 줄 알았다」가 나오면 호출자를 안 센 것이다.
