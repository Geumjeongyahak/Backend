# 리뷰에 보내기 전에 diff 를 훑는 신호

테스트가 통과한 뒤, 리뷰를 부르기 전에 diff를 아래 목록으로 한 번 본다. **도구가
아니라 눈으로 본다.** 2026-09 점검에서 나온 결함 일곱 중 여섯이 이 목록에 걸린다.

| diff에 이것이 보이면 | 뜻 | 나온 곳 |
|---|---|---|
| 반복문 안에 Repository · ProxyService 호출 | N+1 | #229 |
| `findAll` 뒤에 `stream().filter` · `subList` | 전체를 읽고 메모리에서 자른다 | #229 |
| `@Transactional` 안에 업로드 · 다운로드 · 메일 · 외부 API 호출 | DB 연결을 쥔 채 기다린다 | #230 |
| 상태를 확인한 뒤 바꾸는데 락이 없다 | 겹친 요청이 둘 다 통과한다 | #225 |
| 인자 없는 `LocalDateTime.now()` · `LocalDate.now()` | 서버 시간대를 따른다. `Clock` 빈을 쓴다 | #226 |
| `catch (Exception e)`가 예외를 로그에 안 넘긴다 | 원인이 사라진다 | #227 |

## 걸렸다고 전부 결함은 아니다

행 수가 안 늘어나는 테이블의 `findAll`은 괜찮을 수 있다. 관리자만 쓰는 화면의
반복 질의도 그럴 수 있다.

**걸린 자리는 왜 괜찮은지를 PR의 `리뷰어에게`에 적는다.** 적을 근거가 없으면 고친다.

## 이 목록은 늘어난다

codex 리뷰나 운영에서 같은 종류의 결함이 두 번 나오면 여기에 한 줄을 더한다.
[`findings-ledger.md`](../../../findings-ledger.md)가 그 근거다.
