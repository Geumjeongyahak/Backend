# 실제로 커지는 목록만 DB에서 거르기

- 이슈: #229
- 브랜치: `fix/229-list-query-performance`

## 무엇이 실제로 커지나 (2026-09-29 dev DB)

| 테이블 | 행 수 | 증가 | 쓰는 목록 |
|---|---|---|---|
| `lessons` | 2,117 | 월 ~590 | 관리자 수업 목록 (전체를 읽음) |
| `daily_schedules` | 638 | 월 ~200 | 수업일지 목록 (전체를 읽음), 관리자 하루 일정 목록 (기간 상한 없음) |
| `students` | 45 | 거의 고정 | 학생 목록 (학생마다 쿼리) |
| `users` · `posts` · `channels` · `events` | 63 · 31 · 37 · 4 | 거의 고정 | 관리자 목록들 |
| `absence_requests` · `purchase_requests` · `vendor_balance_histories` | 11 · 19 · 3 | 느림 | 요청 목록, 거래처 이력 |

이슈는 목록 열둘을 다룬다. **행 수로 보면 지금 손댈 것은 셋이다.** 나머지는 이 규모에서 고쳐도
차이가 없고, 인덱스는 수백 행 규모라 효과가 없다(규칙: 행 수 없이 인덱스를 만들지 않는다).

## 무엇을 바꾸나

| 번호 | 목록 | 지금 | 바꾼 뒤 |
|---|---|---|---|
| 1 | 관리자 수업 목록 | 수업 전체(2,117행)를 읽고 자바에서 날짜 · 상태로 거른다 | 날짜 범위를 DB 조건으로 넘긴다. 날짜를 안 주면 **이번 달**. 이미 있는 저장소 메서드(`findAllByIsDeletedFalseAndDateBetween…`)를 쓴다 |
| 2 | 관리자 하루 일정 목록 | 시작 · 끝 날짜를 모두 주면 기간 제한이 없다 | 일반 API와 같은 42일 상한. 넘으면 400 |
| 3 | 학생 목록 | 학생마다 분반 조회 (학생 45명이면 쿼리 ~48개, 실측 5명에 8개) | 학생과 분반을 한 번에 읽는다 (`@EntityGraph`) |

1은 페이징과 정렬을 여전히 자바에서 하지만, 대상이 한 달치(~600행)로 줄어 행 수가 늘지 않는다.
DB 페이징까지 가려면 관리자 화면의 정렬 옵션을 SQL로 옮겨야 해서 이번에는 하지 않는다.

## 이번에 안 하는 것 (이슈에서 뺄 것)

| 항목 | 이유 |
|---|---|
| 수업일지 목록 DB 페이징 | 「일지 작성 여부」가 수업 테이블의 메모로 정해져, DB에서 거르려면 하루 일정 도메인 저장소가 수업 테이블을 직접 조회해야 한다(도메인 경계 위반). 지금 638행, 연 ~2,400행이라 몇 년은 괜찮다 |
| 관리자 게시글 · 사용자 · 행사 · 채널 목록 DB 페이징 | 각 수십 행 |
| 결석 · 구입 요청 목록, 거래처 이력 N+1 | 페이지 크기로 묶여 있고 행이 수십 개 이하 |
| 부서 목록 반복 쿼리, 교원 신청 메모리 페이징 경고 | 부서 6개, 신청 1건 조회 |
| 인덱스 | 수백 행 규모 |

## 실패 경로

| 상황 | 결과 |
|---|---|
| 관리자 수업 목록에서 날짜를 하나만 준다 | 준 날짜부터 한 달, 또는 한 달 전부터 준 날짜까지 |
| 관리자 하루 일정 목록 기간이 42일을 넘는다 | 400. 일반 API와 같은 검증기(`DailyScheduleRangeValidator`)를 쓴다 |

## 테스트 (먼저 쓰고 실패를 본다)

쿼리 수는 Hibernate `Statistics`로 센다(테스트 설정에서만 켠다).

| 층 | 테스트 | 고치기 전 |
|---|---|---|
| 통합 | 학생 5명과 15명일 때 학생 목록의 쿼리 수가 같다 | 실패 |
| 통합 | 관리자 수업 목록이 날짜 범위 밖 수업을 DB에서 읽지 않는다 (읽은 엔티티 수로 확인) | 실패 |
| 통합 | 관리자 하루 일정 목록에 43일 기간을 주면 400 | 실패 |
| 회귀 | 기존 관리자 화면 · 학생 API 테스트가 그대로 통과한다 | — |

## 작업

1. 테스트 셋 → 실패 확인 → 커밋 `test(…): …`
2. 학생 목록 `@EntityGraph` → 커밋 `fix(student): …`
3. 관리자 수업 목록 날짜 범위 → 커밋 `fix(lesson): …`
4. 관리자 하루 일정 기간 상한 → 커밋 `fix(daily-schedule): …`
5. 이슈 본문의 범위를 위 표에 맞게 고친다
