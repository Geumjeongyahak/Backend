# 서버 시간대와 애플리케이션 시간대를 한국 시간으로 맞춘다

- 이슈: #226
- 브랜치: `fix/226-timezone-mismatch` (`fix/225-purchase-request-concurrency` 위에 쌓음. #232가 병합되면 `dev`로 옮긴다)

## 무엇을 바꾸나

애플리케이션이 뜰 때 JVM 기본 시간대를 `Asia/Seoul`로 정한다. 인자 없는 `now()` 58곳, JPA의
`createdAt`·`updatedAt`, 로그 시각이 모두 이 값을 따르므로 **한 곳을 고치면 전부 맞춰진다.**
58곳을 `now(clock)`으로 바꾸지 않는다.

```java
@SpringBootApplication
public class GeumjeongyahakApiApplication {

    // 서버 OS 시간대와 상관없이 한국 시간으로 동작한다. 테스트도 이 클래스를 읽으므로 같이 적용된다.
    static {
        TimeZone.setDefault(TimeZone.getTimeZone("Asia/Seoul"));
    }
```

`main()` 안이 아니라 클래스 초기화에 두는 이유: `@SpringBootTest`는 `main()`을 안 부르고 이 클래스를
설정으로 읽기만 한다. 초기화 블록은 두 경우 모두 돈다.

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 방식 | JVM 기본 시간대 한 줄 | 58곳 교체는 엔티티가 `Clock`을 받게 바꿔야 해서 변경이 크다. 기본 시간대 하나면 전부 맞는다 |
| 위치 | 애플리케이션 클래스의 초기화 블록 | 서버 실행 옵션(`-Duser.timezone`)은 배포 스크립트에 있어 로컬·테스트에서 빠진다 |
| 테스트 JVM | `build.gradle`에서 `user.timezone=Asia/Seoul`로 띄운다 | 운영과 같은 조건이다. 아래 「구현 중에 고친 것」 |
| `Clock` 빈 | 그대로 둔다 | 이미 `Asia/Seoul`이다 |
| 스키마 | 안 바꾼다 | 컬럼은 시간대 없는 `timestamp`이고, 넣는 값이 한국 시간으로 통일된다 |

### 이슈에서 뺀 것

이슈의 Must 중 둘을 뺀다. 사람이 「린트까지는 과하다」고 정했다.

- `src/main/java`에 인자 없는 `now()`가 남지 않는다 → 기본 시간대로 맞추므로 남아도 된다
- 규칙을 어기는 코드가 들어오면 테스트가 실패한다(구조 테스트) → 하지 않는다.
  대신 리뷰 전 diff 점검 목록(`harness/.../rules/diff-signals.md`)에 이미 있다

## 실패 경로

| 상황 | 결과 |
|---|---|
| 누가 나중에 `TimeZone.setDefault`를 다른 값으로 부른다 | 이 레포에 그런 코드는 없다 |
| 서버 실행 옵션에 다른 시간대가 들어간다 | 초기화 블록이 나중에 돌아 덮어쓴다 |
| 이미 UTC로 저장된 dev 데이터 | 그대로 남는다. 아래 「안 하는 것」 |

## 테스트

### 구현 중에 고친 것

처음 계획은 테스트 JVM을 dev 서버처럼 UTC로 띄우고, 저장 시각이 한국 시간인지 보는 E2E 셋을 두는
것이었다. 고치기 전에는 셋 다 9시간 차이로 실패했다(커밋 `test(global): …`에 남아 있다).

고친 뒤 전체를 돌리니 **1,104개 중 206개가 실패했다.** 테스트는 `main()`을 안 거쳐서, 시간대가 UTC로
시작했다가 Spring이 시작 클래스를 읽는 순간 한국 시간으로 바뀐다. 그 전에 뜬 H2가 UTC를 기억해 두어
날짜가 하루씩 밀렸다(`2026-06-01` → `2026-05-31`). 운영에서는 `main()`이 가장 먼저 시작 클래스를
읽으므로 이 문제가 없다.

그래서 테스트 JVM은 처음부터 한국 시간으로 띄운다. 그러면 새 E2E 셋은 고친 코드를 빼도 통과하므로
(무엇이 깨졌을 때 실패하는지 댈 수 없으므로) 지운다.

### 운영 경로 확인

빌드한 jar를 **UTC JVM**(`-Duser.timezone=UTC`)과 dev 프로필로 로컬 PostgreSQL 18에 띄웠다.

| 확인 | 결과 |
|---|---|
| 로그 시각 | `+09:00` |
| Flyway `installed_on` | 21:15 (그때 한국 21:16, UTC 12:16) |

## 작업

1. 테스트 JVM을 UTC로 + 저장 시각 E2E 셋 → 실패 확인 → 커밋 `test(global): …`
2. 초기화 블록 한 줄 + 테스트 JVM을 한국 시간으로, E2E 셋 제거 → 전체 통과 · jar를 UTC로 띄워 확인 → 커밋 `fix(global): …`
3. 문서: `docs/tech_spec.md` 또는 해당 문서에 「서버 시간은 한국 시간」 한 줄 → 커밋 `docs(global): …`

끝난 기준: `verify.sh` 통과, UTC JVM으로 띄운 jar가 한국 시간을 기록한다.

## 안 하는 것

- 이미 UTC로 저장된 dev 데이터 보정. dev는 테스트 데이터이고, 어느 칼럼이 UTC였는지 행마다 가릴 수 없다
- 58곳을 `Clock`으로 교체
- 컬럼 타입을 시간대 포함 타입으로 바꾸는 것, API 응답에 시간대 넣기
- 구조 테스트·린트
